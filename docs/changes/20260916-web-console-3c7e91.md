## Goal and acceptance

- Deliver the simple real-data Web console requested after the design: overview, host sampling,
  persistent projects/milestones and Task/Run associations, registered public Tasks, Agent
  diagnostics, Run/Attempt events and artifact summaries.
- Serve with a loopback-only authenticated HTTP gateway; exclude private evaluator data.
  No remote execution controls, model calls or simulated product data.
- Validate persistence, HTTP boundaries, frontend build/types and real browser interactions.

## Changes

- React console has eight navigation entries, responsive layout, loading/error/empty states,
  project editing and conflict handling, resource charts, trace filtering/pagination and artifact metadata.
- Bootstrap composes `agent-infra web`; HTTP gateway handles authentication and transport;
  `runs.console` composes safe read views; Agent module owns native-text presentation.
- Resources owns one shared bounded sampler. Records adds `list_runs` and a separate revisioned
  project catalog. Existing execution schemas and immutable history are unchanged.
- Added [startup/API/limits guide](../operations/web-console.md), optional browser fixture/check,
  backend tests, README navigation and a proposed post-merge project overview.
- Updated [design status](../architecture/web-console-design.md) to distinguish partial implementation
  from later Run control, streaming, multiuser and batch proposals.

## Decisions

- Single local administrator, random per-server bearer token, strict Host and same-origin access;
  token removed from URL and kept in per-tab sessionStorage. No multiuser authorization claim.
- Reuse React/Vite and Python standard-library HTTP; no new production dependencies or lock changes.
- Project progress comes from user-maintained milestones, not execution status or invented percentages.
- Events are persisted historical records, typically imported after Agent phase completion. Show
  bounded text summaries, never raw CAS references or evaluator-private data. Arbitrary Agent text
  is not automatically secret-redacted; the console remains administrator-only.
- Resource history is bounded service-memory observation, not a durable scheduler allocation ledger.

  Records directories; rollback must not delete execution evidence.
