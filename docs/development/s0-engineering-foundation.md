# S0 工程基础开发计划

状态：仓库工程实现与本地验收完成；待任务分支合并。范围为仓库内可复现的工程基础；验收证据见[任务记录](../changes/20260915-s0-foundation-b7e492.md)。

## 目标与边界

没有对话历史的新成员，可以按 README 安装依赖、检查、测试和构建，知道代码归属、公开接口边界以及提交方式。采用单个 Python 发行包和一个 Web 工作区，先支持 Linux 开发环境。

S0 不实现运行状态机、业务 API、测试替身、真实 Agent、Docker、Ray、数据库或 benchmark。它们分别在 S1 契约阶段和后续真实集成阶段交付。空目录和启动页面不代表业务能力。

## 实施顺序

| 步骤 | 交付内容 | 验收 |
| --- | --- | --- |
| 1. 源码归属 | 将空的全局横向分层迁移到功能模块；同步规则与架构说明 | 不保留两套目录；Python 模块可导入，导入不启动外部服务 |
| 2. 工具链 | 固定 Python、Node、uv、pnpm 基线，生成真实锁文件 | 锁定安装成功；Python wheel 和 Web 均可构建 |
| 3. 开发入口 | 最小 CLI、配置装配、Web 起始页，统一 Make 入口 | CLI 提供版本和配置校验；非法配置明确失败；Web 可启动和构建 |
| 4. 自动检查 | Python 格式、lint、类型、导入边界、测试；Web 格式、lint、类型、构建；文档及规则镜像检查 | 本地和 CI 使用相同命令；关键边界有拒绝非法依赖的验证 |
| 5. 协作配置 | CONTRIBUTING、PR 模板、CODEOWNERS、编辑器配置、安全配置示例 | 新成员无需对话历史可完成贡献流程；实际负责人未定时明确临时维护人 |
| 6. 复现与收尾 | 在独立临时目录验证锁定安装、检查、构建及 wheel 安装使用；更新状态记录 | 不依赖原工作区虚拟环境；记录执行结果与限制 |

完成以上验收后，再写四人分工文档，按 S1 接口协作和 S2 单机集成安排任务。

## 各模块在 S0 做到哪里

| 目录 | S0 交付 | 后续实现 |
| --- | --- | --- |
| `agents/` | 包入口、职责、依赖边界 | 会话契约、能力声明、真实适配器 |
| `environments/` | 同上 | 管理/访问契约、工作区、进程、Docker |
| `runs/` | 同上 | Run/Attempt 生命周期和协调 |
| `tasks/` | 同上 | 可见任务视图、原生解析、评测 |
| `resources/` | 同上 | 资源租约、本地派发、Ray |
| `records/` | 同上 | 事件、轨迹、产物持久化 |
| `contracts/` | 无业务类型的共享包边界 | 少量跨模块标识和引用 |
| `gateways/` | CLI 工程入口；HTTP/MCP/Worker 职责定位 | 业务协议转换及权限检查 |
| `bootstrap/` | 无副作用的配置装配 | 实际后端选择和依赖注入 |
| `src/web/` | React/TypeScript 工程和可启动页面 | 基于公开 API 的资源、运行和对话界面 |

不预建尚未确定的 `api.py` 方法或后端类。S1 为各模块添加公开契约时，同步完善导入边界规则；业务模块不能反向依赖接入层或装配层。

## 验收范围与托管边界

必须完成：锁文件严格安装、格式与静态检查、模块依赖检查、配置/CLI 行为测试、规则与本地文档链接检查、前后端构建、独立安装 smoke 检查。基础检查不需要 Docker、GPU、API 密钥或其他节点。

GitHub CI 配置属于本次交付，但远端执行结果和分支保护生效需要发布后在 GitHub 验证；本轮不推送、不创建 PR、不更改仓库托管设置。仓库工程实现完成与远端集成验收分别记录，不能用本地通过替代托管证据。LICENSE 尚未决定，不自行指定开源授权。

版本和安装行为依据：[uv 锁定与同步](https://docs.astral.sh/uv/concepts/projects/sync/)、[Vite 开发前提](https://vite.dev/guide/)、[pnpm 安装](https://pnpm.io/installation)。具体采用版本以仓库清单和锁文件为准。

## 本次落实结果

采用 Python 3.12.14 / uv 0.12.10、Node 24.18.0 / pnpm 10.32.1，具体依赖由锁文件固定。后端暂时零运行时第三方依赖，TOML 配置使用标准库；FastAPI、Docker、Ray 随相应能力引入。Web 使用 React、TypeScript 和 Vite；Ruff、mypy、import-linter、pytest 与 Biome 组成基础检查。

`make setup`、`make verify` 和 wheel smoke 在独立临时 Git 工作目录中通过，包含 17 项测试。Web 开发服务经本机 HTTP 请求及 TSX 转换检查；没有执行浏览器交互测试。CI 配置通过 actionlint 1.7.12 静态校验，托管执行待发布后确认。

后续从 S1 开始协商公开契约、错误/取消语义和可用替身。当前导入检查约束模块方向和同层独立性；公开 API 与内部实现的精细检查随 S1 契约一起补齐。实际人员未指定，CODEOWNERS 暂时使用仓库维护者账号。
