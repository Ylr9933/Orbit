# S1 开发计划：最小契约、测试替身与任务样例

状态：**待用户评审的计划，尚未开始实施。** 本轮仅编写计划，后续开发方式由用户决定。

依据：[模块架构](../architecture/agent-environment-modules.md)、[开发顺序](development-sequence.md)、[四人具体分工](four-person-collaboration.md)。S0 已提供工程目录、依赖、检查和构建；S1 要让各模块能够通过共同接口独立开发并连接起来。

## 1. 目标与范围

S1 的目标是：**每个模块知道接收什么、返回什么、如何处理关键错误，并能通过统一测试替身验证协作。** “契约”包括公开数据类型、调用接口及其行为约定；“测试替身”是可控制成功和失败结果的测试实现。

围绕一条最小链路开展，不一次设计所有未来功能：

```text
提交任务 → 解析任务与可见输入 → 分配资源 → 准备环境
        → 执行 → 冻结并归档产物 → 评测 → 清理与确认释放
```

这条链路在 S1 中通过测试运行。Tasks 样例解析、可见性处理和小型评分逻辑应当真实可验证；Agent、环境执行、资源分配与记录后端使用明确的替身。它证明接口与协调逻辑成立，不证明 Docker 隔离、GPU 限额或真实 Agent 已接通。

**纳入 S1：** 最小公开契约、两个任务样例、共享替身、契约测试、最小 Run 协调逻辑、必要的序列化/schema 生成与一致性检查。

**留到后续：** Docker/Local 真实执行、真实 Agent、完整原生 benchmark 接入、持久数据库与产物存储、HTTP/MCP/Worker 服务、Web 业务页面、Ray、多节点和自然语言建环境。S1 不增加这些组件的生产依赖。

## 2. 需要交付哪些最小接口

以下是能力清单，**不是已经确定的方法签名或字段定义**。实现前由提供方与直接调用方共同收敛。

| 模块 | S1 最小范围 | 主要交付者与使用者 |
| --- | --- | --- |
| Tasks | 固定版本任务引用、解析结果、Agent 可见输入、环境/资源要求、预算与输出约定；小型评测输入输出 | C 提供，A 协调使用，B 接收执行要求 |
| Agent | 能力声明、输入与会话引用、执行结果和取消；区分外部关联与托管模式，不假定所有后端支持交互/恢复 | C 提供，A 使用；执行依赖 B 的接口 |
| Environment | 管理侧的准备、收集、清理；访问侧的受限文件/命令执行与结果查询、停止；返回实际清理结果 | B 提供，A/C 使用 |
| Resources / Worker | 资源请求、分配/租约引用、派发请求、取消等待与确认释放；Worker 接收方式先通过替身验证 | A 提供，Run 使用，分配结果传给 B |
| Run / Attempt | 提交与查询的最小用例、阶段与结果、关联信息、取消/超时；通过注入模块接口完成协调 | A 提供，D/B 的后续接入层使用 |
| Records | 元数据保存与读取、事件追加与增量读取、轨迹/产物引用、归档结果；事件可关联来源和 Attempt | D 提供，A/B/C 使用 |
| 共享契约 | 真正跨模块复用的标识、引用和通用事件封装；可序列化类型的版本与兼容约定 | A 协调，具体提供方和消费者共同确认 |

第一条样例只需要一个 Attempt；保留 Run/Attempt 的关联，不实现完整自动重试与恢复系统。任务协议的预算和重试限制要能表达，不允许替身默认无限重试。

模块公开契约放在所属模块的 `api.py` 或 `api/`，共享目录保持小。接口不携带 Docker 客户端、Ray 句柄或数据库会话。模块内部类型不能直接作为全部对外协议；D 在本阶段只参与提交/查询的用例和样例设计，不同时实现完整 HTTP API。

## 3. 两个任务样例与统一替身

建议先使用两个很小、无外部服务依赖的项目内样例，避免下载数据集或依赖模型密钥。两者保留不同的材料结构，通过轻量任务索引（meta-spec）引用，不强制整理成完全相同的目录。

| 样例 | 结构与约定 | 验证重点 |
| --- | --- | --- |
| 文件结果任务 | 任务说明与公开输入在简单目录中，输出一个约定文本文件；私有校验材料单独存放 | 基础解析、输出缺失、可见输入隔离、明确的通过/不通过结果 |
| 表格预测任务 | 说明、公开 CSV 数据和评测材料分布在嵌套目录，输出按行标识关联的预测文件 | 不同目录适配、材料引用、格式检查、已知预测文件的评分与简单汇总 |

它们是平台契约样例，不代表接入了某个官方 benchmark，也不在 S1 中进行真实模型训练。每个样例包含任务版本、可见性声明、环境要求、输出约定、小型评分规则、正确/错误的固定产物及预期结果。私有材料只用于测试逻辑隔离，真实容器隔离留到 S2 验证。

替身由各接口提供方维护在 `tests/fakes/<module>/`，其他成员复用同一份。替身应能设置成功、失败、超时、取消和清理失败等结果，并记录调用顺序，支持断言“没有提前启动”“没有提前释放”。不能只提供永远成功的空实现，也不能作为生产后端失败时的静默回退。

样例解析器和评分逻辑放 `src/agent_infra/tasks/`，小型任务材料放 `examples/task-packages/`，固定测试产物放 `tests/fixtures/`。Run 的最小协调逻辑放 `runs/`，测试使用替身注入；S2 在同一逻辑上连接真实后端，避免再写第二套协调流程。

## 4. 四人如何推进

沿用现有按内部相关性划分的角色；本表只列 S1 交付，不重复长期职责。

| 角色 | S1 要完成什么 | 需要共同确认的边界 |
| --- | --- | --- |
| A：运行与调度 | Run/Attempt、资源/派发契约和替身；最小协调用例；主集成测试；公共类型与组装协调 | 与 B 确认资源落实和清理，与 C 确认执行/评测，与 D 确认记录失败处理 |
| B：环境与工具 | 环境管理/访问契约、文件/命令与取消语义、环境替身和契约测试；梳理后续 MCP 映射 | 与 A 确认生命周期；与 C 确认可用执行能力；与 D 确认日志与产物归档 |
| C：Agent、任务与评测 | Agent 契约与替身；两种任务解析、可见视图、小型评分逻辑与测试 | 与 A 确认任务输入、预算和结束条件；与 B 确认环境要求；与 D 确认轨迹/评分引用 |
| D：记录与入口 | 记录/事件/产物契约、内存记录替身、写入/查询测试；最小序列化 schema 与调用样例 | 与事件产生方确认来源、去重与结果；与 A 确认提交/查询的用例边界 |

建议按三个批次推进；这是交付顺序，不要求每批都创建一套新分支：

1. **接口与样例约定。** 选定两个样例，提供方起草最小协议和错误语义，直接调用方评审；先收敛少量共享标识与引用。
2. **独立实现。** 各自开发公开契约、样例逻辑、替身和契约测试；A 同步搭建协调用例，不等待所有模块“全部完成”。
3. **集成验收。** 使用同一组替身串起最小链路，加入失败路径，生成 schema 并校验一致性，更新贡献说明与阶段证据。

对需要序列化的最小契约，确定一个维护源，生成对应 schema 到 `schemas/` 并检查是否过期；不要求把全部 Python 内部对象都导出为 schema。具体类型/校验工具和 schema 范围在实施前选择，依赖和锁文件随选择一起更新，不在本次计划中预装。

本计划从已合并的 `main` 创建 `docs/s1-plan`，后续计划修订继续使用该分支。正式开发分支如何分配由用户决定；若以后从未合并分支继续派生，交接时必须说明包含哪些前置提交、PR 会一并带入哪些内容。

## 5. S1 验收标准

所有检查应能在 S0 的开发环境运行，无需 Docker、GPU、集群或 Agent 凭据。实际实现时接入现有 `make check` / `make test` / `make build`，新增命令需随实现提供说明；本计划没有新增可执行命令。

| 验收项 | 通过条件 |
| --- | --- |
| 任务解析与可见性 | 两种结构都能确定性解析；缺失材料报错；Agent 可见对象不包含私有材料及其访问引用 |
| 模块独立性 | 提供方与消费者使用同一契约和替身；保留 S0 导入方向检查，增加跨模块访问公开接口、禁止导入私有实现的检查与反例 |
| 成功链路 | 一个 Attempt 经解析、分配、准备、模拟执行、归档、样例评分和清理完成；能查询对应事件和产物引用 |
| 前置失败 | 非法任务、能力不匹配、资源不可用、环境准备失败不会继续启动 Agent；对已经获得的资源安排对应收尾 |
| 执行与取消 | 执行失败、超时、等待中/运行中取消都有明确结果；重复取消不会重复启动、重复释放；失败后仍安排必要清理 |
| 结果与清理分开 | 缺失产物、归档失败、有效零分、评测失败、清理失败分别可识别；清理失败不把资源记为空闲，也不覆盖已得到的分数 |
| 记录行为 | 可追加和增量读取事件、按约定去重、关联 Attempt；记录写入失败可观察，不能把未保存的结果报告为已可靠归档 |
| 评分与 schema | 固定产物得到预期结果；最小 schema 能从维护源重建，样例校验与过期检查通过 |

内存记录替身通过测试，不代表跨进程重启后仍能查询；替身返回“已清理”，不代表真实容器与 GPU 已回收。这些能力必须在 S2 有对应真实证据。
