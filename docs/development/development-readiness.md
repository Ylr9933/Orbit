## 本次补充的少量约束

1. **明确任务边界**：实现前明确验收标准、受影响模块/公开接口与所需检查；并行任务协调重叠文件与接口变更，不为边界内常规工作重复索要批准。
2. **落实公开接口与真实结果边界**：跨模块不直接调用实现细节；替身和占位输出显式标识，真实接入失败时不能静默换成假结果并报告成功。
3. **明确实机验证范围**：Docker/GPU/多节点测试事先识别目标节点、资源和时间预算，只清理本任务拥有的环境与作业。
4. **避免规则漂移**：AGENTS.md 为规范来源，CLAUDE.md 保持相同内容，同一变更同步维护。

这些条款已写入两个根规则文件。原有的禁止直接修改 main、保护他人工作、契约变更更新消费者、依赖与锁文件同步、验证与记录要求继续适用。

## 下一步优先补工具，而不是继续增加长篇规则

- **先完成 S0**：固定支持的工具链版本，落实有效的依赖清单和锁文件、可运行的安装/检查/构建入口、贡献说明和 PR 模板；确定实际模块负责人，再填写 CODEOWNERS。
- **把检查接入 CI**：逐步加入格式与静态检查、类型检查、相关测试、文档链接、两个规则文件一致性检查；有模块实现后补依赖边界与契约检查。有真实检查结果后，再将相应检查纳入托管平台合并要求。
- **再开放模块并行开发**：约定最小公开接口、可用替身、接口测试与集成责任人，持续打通一个单机闭环。真实 Docker/GPU/跨节点检查单独标明运行条件，不能用替身测试代替其验收。
