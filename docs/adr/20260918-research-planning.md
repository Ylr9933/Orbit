# 研究规划快照、确认与文档投影

状态：B01–B04 采用；真实 Agent 交互以[任务记录](../changes/20260918-research-planning-b6f2a1.md)为准。
承接[初始化 ADR](20260918-project-initialization.md)，不变更原始目标、Project ID 或旧 Web catalog。

## 决定与原因

- Brief、Plan、Experiment 保存在同一个 ResearchDraft 内。每次保存生成不可变研究 revision，
  与 Project 元数据 revision 分开。这样确认一个方案时，背景、约束和实验定义也一起固定。
  不为这三个概念分别建相互竞争的状态机，也不新增聊天或推理引擎。
- 自由研究内容使用 Markdown 字符串；需要被后续代码读取的实验 ID、材料引用、指标方向、资源引用结构化。
  草稿允许缺项。格式错误拒绝，信息不足由只读 check 报告；确认研究方向不等于满足执行条件。
- `claims` 记录关键内容的 user/sourced/inference/assumption 来源；sourced 必须有引用。
  不强制每句话标记，也不声称来源字段或 URL 能证明科学真实性。
- 实验输入沿用受控项目相对路径约束，资源请求引用已有 Resources YAML，由原校验器检查。
  不分配资源、不发起 Run，不读取隐藏 benchmark 评测材料，原生 Task 编译留到 C 批。
- 保存需要 expected_revision 与修改原因；事务比较当前研究 revision。
  对刚刚成功保存的相同内容、原因和基线重试返回原 revision。冲突必须先读取最新状态再处理。
- 确认需要当前 revision、内容 digest 和用户决定说明。后续草稿不改写此前确认记录。
  这是本机可信调用者对用户授权的记录，不是独立身份认证或数字签名；Skill 不得把自行建议当作用户授权。

## 存储和升级

沿用本地 Project SQLite，自动事务升级 user_version 1 → 2；只读旧库不升级。
新增研究版本、head 和确认表。研究版本不可变，head 指向最新草稿和最近采用的版本。
原始目标仍位于既有 Project，研究 JSON 不接受 original_goal 字段。

schema 2 写入后，旧 A 批程序会拒绝打开控制库。升级前备份控制状态目录与工作区；
回退使用升级前备份，不能把 user_version 手改为 1 来掩盖格式差异。

## 文件投影和失败恢复

数据库中的研究快照是权威内容；三份 Markdown 默认显示最新草稿，采用状态通过 context 查询。
保存事务同时登记希望生成的文件和允许替换的已知投影内容摘要，然后尝试导出。
导出失败时返回 `saved=true` 和明确的 `projection.status=pending`、冲突路径；不能把保存失败和文档冲突混淆。

后续重试逐文件比较内容：等于目标则跳过；等于此前已登记生成内容则替换；其他内容和删除均保留。
全部成功后清除待投影标记。进程在任意文件替换前后退出均可继续，且用户可以在冲突未解决时保存后续草稿。
投影摘要在保存时登记，因此不依赖多文件写入与 SQLite 的跨介质原子事务。

用户可以显式导入 Markdown 到 background、question 或 plan summary。文件内容完整保存为一个字段，
不自动猜测或抽取科学结论。导入对应的生成文件时，同时登记被读取的内容摘要，允许生成新投影；
导入后又发生的新编辑仍会引发冲突。一般建议从独立笔记导入，避免反复导入完整投影导致标题嵌套。
已保存草稿、修改原因与确认保留历史；文档原始修改也存在所导入的版本内。
