# 0928 实验工作台：调研与设计方案

日期：2026-09-28。状态：**设计提案与离线交互原型，尚未改造或部署正式前端。**

代码基线：`54165f5aa691b38a284c6a35fa71fc2b326e31c0`。样本：本机 ASI-Bench、b3、seed31415、gpt-6-sol / medium 的 60 条有效评分记录。

## 1. 建议定下来的方向

把工作台的首要用途收敛为：**看实验结果，找到值得复盘的任务，理解执行证据，决定下一次实验。**

推荐浅色、中性背景、单一强调色的桌面工作台。主要内容是可操作的任务表；指标、分布、配置、轨迹各有明确位置。先落地实验列表、实验详情和任务详情，再接入重跑和完善比较。保留现有科研能力，通过次级入口访问。

本轮不引入新的前端框架，不重新实现 Records，不增加大屏监控、聊天面板、拖拽流程图或自定义仪表盘。界面复杂度应随用户正在处理的事情增加，而不是随底层模块数量增加。

## 2. 调研依据与取舍

调研范围：官方产品文档与设计系统、仓库当前实现、60 条真实结果、已有自动化测试截图。没有进行用户访谈或线上 A/B 测试；以下采用方式属于结合本项目作出的设计判断。

| 参考 | 官方材料支持的设计方式 | 本项目采用方式 |
| --- | --- | --- |
| GitHub Primer | 数据表中的明确列标题、行标识、排序和行操作 | 任务名称是可点击入口；得分与耗时右对齐，技术 ID 收入详情 |
| IBM Carbon | 表格搜索、筛选、选择、批量操作；复杂内容转入详情或侧面板 | 表格上方只留搜索与常用筛选，选择任务后才出现重跑操作栏 |
| W&B Run Comparer | 并排查看配置与指标差异，支持只显示差异 | 比较页先显示两个实验和共同任务集合，再显示分数变化与配置差异 |
| Langfuse Trace View | 时间顺序与层级视图、观察项详情、搜索 | 先做时间线与步骤详情；命令、输出、消息分开阅读，复杂关系图后置 |
| W3C WCAG | 文字对比度、可操作目标大小、键盘访问等约束 | 作为视觉和交互验收条件；不能只用颜色传达成功、失败或缺失 |

参考链接与访问日期均为 2026-09-28：

- [Primer：DataTable guidelines](https://primer.style/product/components/data-table/guidelines/)。采用表格的内容组织方式，不要求引入 Primer 组件库。
- [Carbon：Data table usage](https://carbondesignsystem.com/components/data-table/usage/)。采用渐进展开与选择后的批量操作，不照搬完整企业后台。
- [W&B：Compare run metrics](https://docs.wandb.ai/models/app/features/panels/run-comparer)。借鉴“配置变化和结果变化放在一起”，不复制大量自定义面板。
- [Langfuse：New Trace View](https://langfuse.com/changelog/2025-03-19-new-trace-view)。借鉴时间线、层级和搜索组织方式；本项目只能显示已采集到的证据。
- [W3C：Contrast Minimum](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)、[Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)。普通正文目标对比度至少 4.5:1；常用控件采用更宽裕的点击区域。

## 4. 用真实样本决定首页显示什么

来源：`benchmark/asibench/b3-gpt-6-sol-codex01571-20260926/summary.json`，以及同目录只读控制库和 Records 清单。

| 事实 | 数值 |
| --- | ---: |
| 任务总数 / 有效评分数 | 60 / 60 |
| 算术平均分 | 35.43277818088395 |
| 中位数 | 19.12277543068594 |
| 零分任务 | 5 |
| 满分任务 | 3 |
| 本次状态中的运行失败 | 0 |
| 单任务实测运行耗时中位数 | 596.0384283906315 秒，约 10 分钟 |
| 任务领域数 | 11 |

展示保留两位小数，导出保留原始数值。页面称为“本地公开评分”。0 分是有效评分，不等同于运行失败。没有有效评分的任务显示“未评分”，不能自动补 0。

推荐顶部四个摘要：**平均分 35.43、有效评分 60/60、零分任务 5、运行耗时中位数约 10 分钟**。中位分 19.12 作为均分下的一行辅助信息。点击“零分任务”直接筛选对应五项。

这里的运行耗时来自受管进程测量，不能命名为纯模型思考时间或训练时间。当前 ASI 求解时限是 10800 秒，即 180 分钟；外层预算是 10920 秒，即 182 分钟。两者在详情中分别说明，避免“预算 182 分钟”被误认成实际耗时或金额。无可靠费用记录时不显示估算金额。

## 6. 三个核心页面

### 6.1 实验列表

默认入口直接展示实验，不增加独立欢迎大屏。

- 列：实验名称、benchmark / 条件、模型、平均分、有效评分覆盖、状态、最近活动。
- 运行中的实验优先；已完成按最近活动排序。
- 单实验一行，名称友好可编辑，内部目录名不成为主标题。
- “登记已有实验”和未来的“新建实验”进入二级操作；空状态只提供一个明确入口。
- 单实验点击进入详情。比较可以从选择两个实验开始，首版限定两个。

### 6.2 实验详情

```text
实验 / ASI-Bench · b3                         比较实验   导出结果
ASI-Bench · b3  [已完成]
gpt-6-sol · medium · seed31415 · Codex 0.157.1

平均分 35.43     有效评分 60/60     零分 5      耗时中位数 10 分钟

任务结果  |  得分分布  |  实验比较
搜索任务…                 领域筛选    得分筛选    排序
□  任务名称                     领域      得分      状态      耗时
□  perturbation convergence…    生物统计   0.00     已评分    …
…
显示 1–20 项，共 60 项                                上一页  下一页
```

桌面首屏目标：1440×900 时出现任务表表头及至少 5 条任务，不让大图表或批次列表挡在前面。

- 默认 20 项一页，可选 50 项；首版不需要虚拟列表。
- 单任务名称进入详情，支持返回保留筛选、排序、分页和滚动位置。
- 查询条件写入 URL；切换 tab 不丢筛选。主标题的平均分始终表示完整实验；如果提供筛选集均分，必须单独标明分母。
- 数值排序用原始数字，不用已格式化的字符串。原始任务标识可通过复制或详情获得。
- 选择任务后才出现批量操作栏，清楚写选择数量与范围；“当前页全选”不能暗中变成全部 60 项。
- 只有一组实验时不显示“实验提升趋势”。得分分布使用直方图；领域结果带样本数，不把某领域 1 项的均分等同于整体能力结论。
- 不默认展示 16 位小数、长哈希、配置 JSON、绝对路径和复杂提示语。

### 6.3 单任务详情

结果先行：分数、评分有效性、实测耗时、执行状态、提交产物入口。运行失败时先显示已确认的失败类型与下一步操作；已评分低分时进入评分细项，不自动判定为环境错误。

四个 tab：

1. **结果**：评分和可解释的评分细项。保留原生评分字段与单位；不同 benchmark 使用其原生细项，不强行套用统一成功阈值。
2. **Agent 轨迹**：按时间顺序列消息、工具调用、命令结果、文件修改。默认折叠长输出；搜索命令或错误；点击一步查看输入/输出。使用真实步骤 ID 深链接。
3. **文件**：优先列评分、提交、报告，再展开全部文件。文本可读预览，二进制显示大小与下载入口。
4. **配置**：用键值表展示模型、思考强度、版本、任务条件、资源和时限；技术字段折叠。

轨迹不是聊天记录的假象：已归档的内容明确是归档；采集不完整、字段缺失和截断必须在对应内容附近体现。不得把平台生命周期事件包装成模型对话，也不推测未记录的推理内容。

桌面可采用“步骤目录 + 当前步骤详情”的两栏阅读器；窄屏切成单栏。批次/任务/步骤最多三层，不嵌套多层抽屉。

## 7. 视觉与交互规范

| 项目 | 建议 |
| --- | --- |
| 主题 | 首版只做浅色；页面浅灰、内容白色、中性文字，深绿单一强调色 |
| 字体 | 系统无衬线；正文约 14px，表格 12–14px，标题 24–28px；代码才使用等宽字体 |
| 数字 | 等宽数字、右对齐，评分保留两位；单位放列标题或辅助文本 |
| 间距 | 4/8px 基准，常用 8/16/24/32；避免每块都加大空白和独立卡片 |
| 容器 | 1px 细边框，6–8px 圆角；强阴影仅用于弹窗，不做玻璃、渐变背景 |
| 导航 | 约 192px，次级文字清楚可读；不使用大量装饰符号代替明确标签 |
| 按钮 | 一个区域一个主操作；常用控件至少约 36px 高，触屏优先 44px；危险动作与普通动作分开 |
| 状态色 | 成功、错误、等待各有文字标签；零分使用普通数值或弱提示，不标红为运行故障 |
| 图表 | 每个图回答具体问题；首版保留分布、领域汇总和比较差值即可 |
| 加载 | 骨架保留结构；刷新失败保留上次数据并显示时间；没有结果与搜索无匹配分别处理 |
| 响应式 | 1440/1280 桌面优先；窄屏导航收起，指标两列，表格局部横向滚动，页面不整体横向溢出 |
| 可访问性 | 真实链接/按钮、可见焦点、输入标签、表格表头、弹窗焦点管理；动画尊重 reduced-motion |

这些值是本项目建议的统一 tokens，不代表直接照抄外部组件库。原型的观感仍需浏览器检查与用户试用；不能用“用了设计系统”代替验收。

## 8. 比较与重跑怎么接，才不会再次人工改记录

### 比较

已有 `ComparisonPanel` 与后端 `compare_runs` 可以复用，先改成清楚的独立区域。

- 选择基线和候选，首先显示共同有效任务数量。
- 显示共同集合上的两侧均分、逐任务差值及提升/退步/不变数量。
- 输入、seed/split、材料、评分器版本不一致时明确解释；prompt level 等条件差异不能被相同任务名掩盖。模型和思考强度作为实验自变量明确显示。
- 默认只展开配置差异，可查看完整配置。
- 缺失评分不当作 0；不能拿 60 项均分与另一个 10 项均分直接宣布提升。
- 首版不自动作统计显著性或因果结论。当前只有一个样本实验，原型采用真实空状态，不生成第二组假分数。

### 重跑

这是需要补齐的后端流程，不是新增按钮就算完成。

1. 用户选中任务，查看沿用的模型、任务条件、资源和时限。
2. 服务器预检资源、镜像、Agent 和原生协议要求，给出具体阻塞原因。
3. 提交创建新的尝试和唯一 operation ID，双击/刷新使用同一幂等请求，不重复启动。
4. 实验成员持久记录“当前展示结果”与“全部尝试”。新任务运行中时原结果仍可看；完成后按明确的重跑结果选择规则更新展示，不能挑最高分。
5. 页面默认每任务一行，无额外醒目重跑标记；历史尝试在详情中查看。
6. 重跑失败时保留既有有效结果，同时在详情显示新尝试失败；原运行证据和成本记录不靠删除完成归并。
7. 导出保存所选尝试的快照，确保之后重跑不会悄悄改变已导出的比较结果。

原冻结 `BatchPlan` 和历史证据不应被界面改写。实现时在既有工作台/运行协调边界增加实验成员结果选择的持久投影，再连接现有 submit、queue、reconcile、Records。具体接口需要后端单独设计和测试；本轮未实现。

## 9. 前端维护方式

沿用 React/TypeScript/Vite 与现有功能组件，按页面拆分，不新增一套 dashboard 框架。

- `app.tsx` 负责外壳与导航；旧路由保留兼容。
- 现有 `features/benchmark/` 承载实验列表、实验详情、任务详情、比较、轨迹阅读器、文件预览。
- 抽出少量共享的页面标题、指标栏、表格工具栏、状态标签、空状态和对话框。
- 展示格式、时间口径、状态中文名和得分有效性集中处理，不能每页各自判断。
- API 调用保持现有服务边界。每次只请求当前页面所需数据；不为 60 行预加载完整轨迹和文件正文。
- 已完成实验停止周期刷新；运行中使用有界轮询，保留取消与错误状态；轮询不能重置用户展开位置。
- 先统一语义颜色和尺寸 tokens，再替换局部样式；不以整体重写作为美化前提。
- 未接通的正式操作不显示为可点击成功按钮。设计原型的按钮仅用来评审流程。

## 10. 实施顺序与验收

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| U1 页面与视觉基础 | tokens、导航、实验列表与详情；保留旧路由 | 真实 60 项首屏能看到 35.43 和 60/60，搜索、排序、分页、CSV 数值一致 |
| U2 单任务复盘 | 结果优先，轨迹阅读、文件和配置分层 | 从零分任务进入结果与评分证据；已归档轨迹可按步骤查询；返回列表位置不丢失 |
| U3 比较整理 | 基线选择、共同任务集合、配置差异、逐题差值 | 用明确标注的测试数据验证配对、缺失、零分、不兼容；真实第二组数据待后续预算授权 |
| U4 重跑服务与界面 | 持久尝试、幂等提交、状态反馈、结果归并 | 通过接口完成单任务与多任务重跑；刷新/服务重启不重复派发；无需手动 SQLite 操作 |
| U5 实用验收 | 接入一个真实小任务集，检查使用与恢复 | 用户按简短说明独立完成看结果→复盘→重跑→比较；真实模型预算另行按任务确认 |

第一轮代码只实现 U1/U2，已有比较入口保留；U3/U4 分别验收。先用现有记录完成前端验收，不为美化重新运行整套模型任务。

关键检查：

- 60 个任务平均值与 Records/CLI 一致，导出保留完整精度；筛选不悄悄改变实验均分。
- 0 分、缺失评分、执行失败、已取消、清理待完成分别覆盖。
- 新用户“5 秒找到总体结果、30 秒进入某个低分任务证据”作为试用目标，尚未测量。
- 浏览器后退、页面刷新、分享深链接、键盘导航、窄屏、长任务名和超长输出均可用。
- 常见流程不向用户暴露绝对状态目录、数据库路径、租约 ID 等实现细节。
- 正式端到端验收需在可运行浏览器的环境执行；静态原型测试不代表生产系统验收。

## 11. 交付与验证范围

- [离线交互原型](../assets/experiment-workbench-20260928.html)：可用浏览器直接打开，无网络依赖。内嵌 60 条真实结果的精简快照，包括任务名、分数、耗时、轨迹统计与文件清单，不含认证数据或原始消息正文。
- 本文：调研来源、页面设计、数据口径、后端依赖和实施分期。
- 原型资源/设置页为范围说明；比较页为真实空状态；重跑仅预览，不连接模型、Docker 或 Controller。它是独立的设计评审附件，不替代 `src/web/` 中的正式前端，也不随实时运行更新。
- [任务记录](../changes/20260928-workbench-design-60asi-4b7e.md)：归档进度与验证证据。

原型已通过脚本语法、60 条源记录一致性、搜索/筛选/排序、CSV 导出与 HTML 转义检查。浏览器尝试受沙箱限制，Chromium 启动时报 `setsockopt: Operation not permitted`；尚未完成截图、视觉或真实浏览器交互验收。
